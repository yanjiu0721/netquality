# 网络质量探测

看一条路径质量的小工具。可以在 Windows、Linux 和 Android 上用。

有两种发包方式：

- **本机**：这台手机或电脑直接向目标发包，自己计算往返时间。
- **远程节点**：手机只负责选择目标和看结果。真正发包的是你自己的一台 Linux 节点，延迟在节点上用单调时钟量好再传回来，不包含手机到节点的控制通道耗时。

目标可以是合作的 NetQuality 反射器，也可以是已经在跑的业务端口。Minecraft Java（TCP 25565）和基岩版（UDP 19132）有专门的握手。端口都能改。

数字和曲线只来自已经完成的探测。没有内置假样本，也不会在还没探完时画出 100%。

## 为什么结果要分开看

合作反射器会把探测包送回来，这时可以算「探测无应答」：发出去了，超时前没有对上序号的回显。TCP 会自己重传，所以这个数字不是网卡上的物理丢包。

普通 TCP 只看能不能连上、连接花了多久、失败了几次。它不使用自定义探测帧。

普通 UDP、DNS、基岩版如果根本没有协议应答，记为「无应答 / 未知」，不能当成已经证实的丢包。收到了包但内容不对，记为协议错误。

域名解析失败、连接被拒绝、超时、节点口令错误、协议不符，界面上会用短句分开说明。

## 本地演示

需要 Go 1.22+。桌面客户端需要 Flutter（本仓库用 3.47 开发）。Linux 桌面还需要 `clang`、`cmake`、`ninja`、`pkg-config` 和 GTK 3。

终端 1：

```bash
cd server
go build -o netquality-reflector .
./netquality-reflector
```

默认只做反射器：TCP `19090`、UDP `19091`。

终端 2：

```bash
cd client
flutter pub get
flutter run -d linux
```

来源选「本机」，目标保持 `127.0.0.1`，类型选「合作反射 TCP」或「合作反射 UDP」，点「开始探测」。延迟应是零点几毫秒这一量级。点「停止探测」后不再发包。

本机演示只能证明程序在工作。要看真实线路，把反射器装到服务器上，或者让一台节点去测你的业务端口。

## 在 App 里选节点和目标

1. 「探测来源」选「本机」或「远程节点」。
2. 远程时点「管理节点」。名称自定。地址写成 `https://你的域名:8443` 这种控制地址，不要把口令写进地址。公开节点的口令留空；私有节点把节点口令填在这一栏。它和目标回显口令不是同一个。
3. 「目标」填要测的主机、端口和类型。合作反射的默认端口是 TCP `19090`、UDP `19091`。Minecraft Java 默认 `25565`，基岩版默认 `19132`。HTTP 不单独填端口：写成 `https://www.cause-by-siky.top:2025/` 这样的完整网址，或只写主机名。只写主机名或 IP 时按 `http://主机/`，端口是 80。HTTP 超时默认 5000 毫秒。
4. 点「开始探测」。远程任务到设定的时长后节点会自己停，也可以提前点停止。停止或断开都会让节点结束这次任务。

本机的 UDP 探测会记下这次解析出的每个地址。结果上的「实际地址」是真正发包或连通的地址，并注明 IPv4 或 IPv6。域名解析出来的地址单独标成「解析到」，不会被说成已经在用。还没有哪个地址应答时，一次失败就换下一个，这次失败不计入正式丢包，界面会说明回退；已经有应答之后，超时算正式结果，要连续三次没有应答才换。全部地址都失败时显示失败，不会显示 0% 成功。地址落在 `198.18.0.0/15` 时，界面会标明这是 VPN 假地址。

远程节点从 1.1.2 起会在每条结果里带上实际地址。更早的节点没有这个字段时，界面写明「节点没有报告实际使用的地址」，不会在手机上另做一次解析来冒充。1.1.1 的节点仍会把选址失败算进统计。

端口框写着当前类型的默认端口。合作反射 TCP 是 19090，UDP 是 19091。只有端口仍是上一种类型的默认值，或端口是空的，切换类型才会自动更换。HTTP 模式不显示这个端口框。

已有远程节点可以改名称、控制地址和口令。节点编号和当前选择不变。口令留空表示不改，界面不显示已经保存的口令。

手动停止后曲线还在，并给出这次的开始、结束、用时和最终指标。停止时还没完成的请求不算丢包。点曲线可以钉住该时刻，松手后仍然保留。指标的算法在应用里的「指标说明」，版本记录在「更新历史」。

节点口令保存在本机应用目录里，权限尽量收成只有自己能读，不会写进网址或日志。

## 装到自己的 Linux 服务器

步骤、公开/口令两种例子、防火墙和 HTTPS 在 [docs/server-linux.md](docs/server-linux.md)。不要把真实口令写进仓库或命令历史以外的公开地方。

只做反射，给本机或节点回显用。端口和口令写在 `server/.env`，不改就是 TCP `19090`、UDP `19091`：

```bash
cd server
go build -o netquality-reflector .
./netquality-reflector
```

同一台机器既回显、又替手机探测别的目标：

```bash
./netquality-reflector -mode both -bind 0.0.0.0 -tcp-port 19090 -udp-port 19091 -control-addr 127.0.0.1:8443
```

控制端口默认只听本机。放到公网前，用 HTTPS 反向代理，或加上 `-tls-cert` 和 `-tls-key`。没设置 `-node-token` 时节点是公开的，谁能连上谁就能发起有上限的探测，程序启动时会警告。设置了节点口令以后，所有创建、停止、查看和结果流都会先校验，不对就不会向目标发包。

远程节点默认不探测本机、内网、链路本地和云元数据地址。要在机房里故意测局域网时，才加 `-allow-private`。元数据地址仍然禁止。

## 开发

```bash
cd server && go test -race ./...
cd client && flutter analyze && flutter test
```

Android 安装包是按 CPU 分开的 release 包，使用调试证书，只适合测试安装，不是应用商店签名。当前版本名 `1.1.4`，构建号 `7`。应用标识没有改。1.1.3 以及以后的版本必须用仓库里的 [client/android/keystore/debug.keystore](client/android/keystore/debug.keystore) 签名，这样后一版才能覆盖安装。1.1.2 的证书不同，升到 1.1.3 要先卸载。

从 1.1.3 起，客户端可以检查更新，设置里可以关掉。从 1.1.4 起可以选择更新源，默认先问 YanJiu Git（`https://git.yanjiu.ltd/YanJiu/netquality/releases`），连不上再问 GitHub Releases。结果里会写明这次实际用的是哪一个。桌面安装包的规范名是 `linux-x64` 和 `windows-x64`，更新器也认以前的 `amd64`、`x86_64`、`aarch64`。1.1.3 的桌面更新器认不出单独的 `x64`。Linux 这一版另外提供内容相同的 `linux-x86_64`，1.1.3 的 Linux 会选中它并自己安装。Windows 桌面安装包要在 Windows 上构建，放上内容相同的 `windows-x86_64` 之后，1.1.3 的 Windows 也会自己安装；这份文件还没放上时，Windows 仍要自己安装。1.1.2 没有自更新，升到 1.1.4 仍要自己安装。已经发布的 1.1.2 和 1.1.3 安装包也没有在线更新历史。Windows 和 Linux 会把新文件写回当前安装目录。Android 会弹出系统安装确认，这一步不能跳过。没有真正的新版本时，可以用环境变量 `NQ_UPDATE_GITHUB_API` 和 `NQ_UPDATE_GITEA_API` 指向一份同样格式的测试响应。

中心也是这个 Go 程序。示例配置在 [server/example-center](server/example-center)，里面的口令都是占位。本机可以这样看目录：

```bash
cd server
go build -o netquality-reflector .
./netquality-reflector -mode center -center-dir example-center -control-addr 127.0.0.1:8443
```

客户端点「一键添加服务器」，中心地址填 `http://127.0.0.1:8443`，账号 `lab`，口令 `example-token`。这只适合本机确认功能。真正给别人用时，控制端口要走 HTTPS。

这一版的说明在 [docs/release-notes/1.1.4.md](docs/release-notes/1.1.4.md)。
