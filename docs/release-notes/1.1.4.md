# 网络质量探测 1.1.4

版本名 `1.1.4`，构建号 `7`。署名：言灸。许可：GNU Affero General Public License v3.0（AGPL-3.0-only）。

应用标识和签名没有改。1.1.3 以及以后的安装包沿用仓库里的同一把调试证书，新的安装包会覆盖 1.1.3，不用先卸载。1.1.2 的证书不同，从 1.1.2 升级仍要先卸载。

这一版还没有打 Git 标签，也还没有发布安装包。下面是准备发布的说明。

## 更新源

设置里可以选择更新源：「YanJiu Git」或「GitHub」。默认是 YanJiu Git，因为这边的网络经常解析不到 github.com。检查更新和下载安装都先用选中的源。选中的源连不上，或暂时限制了请求次数时，会自动试另一个，结果里会写明这次实际用的是哪一个。

环境变量 `NQ_UPDATE_GITHUB_API` 和 `NQ_UPDATE_GITEA_API` 仍然可以指向一份同样格式的测试响应。

1.1.2 没有自更新，升级仍要自己安装。

## 更新历史

「更新历史」会向所选更新源读取发布列表，不只看最新一条。已经发布的版本都会列出来，包括比当前安装更新的版本。草稿和不是版本号的标签不会出现。

成功同步后会在本机留一份。网络失败时用上次保存的列表；没有保存过就用安装包里的说明，并标明这份列表可能不是最新。

已经发布的 1.1.2 和 1.1.3 安装包没有这份同步。那些版本不会自己看到以后的发布说明，需要先安装包含这个功能的版本。

## 被截断的说明

表单里放不下一行的提示，末尾会显示省略号。点一下展开全文，再点一下收回。本来就能显示完的短句不用点。

## HTTP 目标

HTTP 探测的目标是完整网址，或只写主机名、IP。完整网址沿用其中的协议、端口和路径。只写主机名或 IP 时按 http，端口 80，不再单独填端口。超时默认 5000 毫秒。

本机找不到或启动不了 `netquality-reflector` 时会立刻说明原因，并建议改用远程节点，不会把这次记成全部失败。Android 安装包不包含这个程序。

## 桌面安装包文件名

已经发布的桌面压缩包文件名是：

- `netquality-1.1.3-linux-x64.tar.gz`
- `netquality-1.1.3-windows-x64.zip`

1.1.3 的更新器只在名字里找 `amd64` 或 `x86_64`，所以桌面端会提示没有适合这台设备的安装包。1.1.3 升到 1.1.4 仍要手动安装。从这一版起，`linux-x64` 和 `windows-x64` 会被认成当前机器的 64 位包。以前的 `amd64`、`x86_64`、`aarch64` 也仍然接受。

名字里带 `server` 或 `reflector` 的包继续跳过，不会被客户端下载。Android 的 `arm64-v8a`、`armeabi-v7a`、`x86_64` 本来就能对上。

这一版准备发布的客户端文件名：

- `netquality-1.1.4-windows-x64.zip`
- `netquality-1.1.4-linux-x64.tar.gz`
- `netquality-1.1.4-arm64-v8a.apk`
- `netquality-1.1.4-armeabi-v7a.apk`
- `netquality-1.1.4-x86_64.apk`
